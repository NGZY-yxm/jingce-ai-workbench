# Blender 预演工作流

镜策的“Blender 预演”将故事、活动主体、道具、摄影机路线和动作节拍组织成通用场景配置，通过固定的本机生成器完成白模与 MP4。人物为简单几何代理，步行动作为预演摆动；不包含精细人物建模、绑定或表情。场景配置可以替换为庭院、房间、街道和其他空间。

## 在网站上使用

1. 安装 Windows 版 Blender 4.x 或更新版本。
2. 打开幻帧 MiraFrame网站，选择工程，进入“Blender 预演”。
3. 下载 Windows 助手，解压，双击“启动幻帧blender助手.cmd”。首次启动自动下载并校验 Node.js 与 imageio-ffmpeg 中的 Windows 编码工具；不需要安装 Python。下载需要访问 nodejs.org 与 PyPI。Blender 使用用户自己安装的版本。
4. 在网站点击“连接本机助手”，在本机助手页面允许当前网站。浏览器出现本地网络访问权限提示时允许访问。保持助手窗口运行。
5. 在“故事与预演对话”的同一个聊天框输入故事和镜头要求，点击“发送”。助手会整理场景方案，检查通过后由用户应用；也可在场景 JSON 中载入并修改免费本地示例。发送使用文字模型接口，不会自动提交付费图片或视频生成。
6. 检查并编辑场景 JSON，确认时长、比例、人物路径、摄影机位置和注视点后，点击“开始本机预演”。
7. 在网页查看任务进度与 MP4。完成后，工程、预演 MP4、俯视路线图与关键帧上传回当前网站工程，媒体登记到素材库。
8. 不满意时点该结果的“对话修改”，在本页说明具体时间段、当前画面、希望的改法和要保留的部分。模型回复显示修改说明与待应用方案，确认应用后检查场景，再开始新的预演。
9. 可下载 MP4/Blender 工程、在本机 Blender 中打开、放到画布或创建后续视频生成项。后续模型需要支持视频参考；相关云存储和生成仍遵循现有模型能力检查与明确提交步骤。

网页不能仅凭电脑安装了 Blender 就直接启动程序。助手承担网站与本机之间的桥接；安装并首次授权之后，日常操作在镜策网页完成。当前助手面向 Windows 和 Chromium 系浏览器，建议使用最新版 Chrome/Edge。其他浏览器如阻止 HTTPS 网站访问回环 HTTP，请使用兼容浏览器；连接失败会在网页明确提示。移动网页可管理结果，但手机无法调用另一台电脑上的助手。

助手固定监听 `127.0.0.1:18973`。只接受回环 Host；远程站点必须为 HTTPS，并在本机助手明确授权。跨站请求限定已授权 Origin，操作需要每个站点独立令牌。令牌保存在当前浏览器本机存储和助手私有文件中；可在助手页面断开授权。只执行固定随包生成器，不执行导入技能脚本、AI 返回代码或任意命令。文件下载使用任务及白名单文件标识，不能指定任意本机路径。

网站 CSP 必须允许 `connect-src http://127.0.0.1:18973`，并保留浏览器的本地网络访问权限。部署反向代理时将 API 的请求体限制设置到至少 300 MB，保持二进制输出回传和媒体 Range 请求。部署系统已有的账号认证、用户工程权限和租户隔离必须同时应用到新增 `/api/previs*` 接口；本实现沿用现有工程访问和操作令牌规则，不会自动给单机版增加多用户账号。本站源码服务本身仍监听回环地址，公网站点由部署代理提供 HTTPS。

应用进程设置 `JINGCE_PUBLIC_ORIGIN=https://你的镜策域名`（不含路径或结尾斜线），允许该网站的同源操作。反向代理向后端传递本机 Host，例如 `proxy_set_header Host 127.0.0.1:18970;`，端口应与实际进程一致；保留浏览器的 `Origin`，不要统一清除或替换跨站请求的来源。HTTPS 站点会自动选择本机助手，服务器无需安装 Blender。

## 在当前创作工程中管理多个预演工程

预演页顶部的“新建预演工程”会在当前创作工程内添加 Blender 预演工程；顶部下拉框只列出当前创作工程的预演工程。每个预演工程分别保留故事、场景 JSON、对话、待确认方案、历史版本和渲染记录。预演工程列表和渲染记录保存于网站工程中，编辑草稿与最后选择继续保存在当前账号的浏览器本地存储中。切换或刷新后会恢复相应草稿。

原有单份预演草稿与没有子工程编号的历史任务归入“预演工程 1”。生成的媒体继续登记到所属创作工程的素材库，可用于同一创作工程的画布和视频参考。新建预演工程只建立空白编辑工作区，渲染仍由“开始本机预演”提交。

## 用同一个聊天整理故事、修改和修复场景

右侧任务的“对话修改”将该任务的场景复制为当前修改起点，原任务与媒体保留。左侧“故事与预演对话”既可从新故事建立场景，也可以先讨论原因或提出修改，例如“第 3–5 秒人物被桌子挡住，让他从左侧绕过，保留结尾两人同框”。每轮请求携带故事要求、当前场景或待确认方案、所选预演参数和最近最多 20 条有效对话。当前接口只发送场景数据和文字，不会自动发送 MP4、截图或路线图，因此请用文字描述预演画面。

模型可以返回纯讨论回复，也可以给出完整的修订场景。场景通过数据校验后才形成待应用方案。页面依据真实 JSON 变化展示焦距、摄影机路线、主体和道具等改动；连续讨论尚未应用的方案时，以该待应用方案作为下一轮基础，改动列表仍对比当前编辑框。点击“应用到场景编辑框”只替换场景草稿；需再次检查并点击“开始本机预演”才会渲染。

发送后修改了场景或故事时，旧方案会提示已失效并禁止覆盖新编辑。调用失败保留反馈，不自动重发；无效场景显示校验原因，已有场景保持原样。即使用户正在编辑的 JSON 有语法错误或不支持的字段，也可继续发送消息，原始 JSON 与具体检查错误会一起进入模型上下文。模型上次返回的无效场景同样保留原始回复，可展开查看；下一轮会带入原文和错误，方便继续修复。“请 AI 修复场景”只填写聊天输入，用户点击“发送”后才调用模型。应用方案、载入示例和切换到已有预演前自动保存场景版本，可在“恢复之前的场景版本”中恢复；恢复本身也保留恢复前的场景。最近 20 个场景版本、24 条对话、输入草稿和待应用方案按工程保存在当前浏览器，刷新或工程切换后可继续，跨浏览器或设备不会同步这段对话。

故事摘要与场景 JSON 放在同一聊天区的折叠编辑中；已有工程草稿、故事与对话继续保留。这里使用所选语言模型和已有文字接口；发送会产生该文字接口的用量。讨论、应用和恢复均不会自动启动 Blender，也不会提交图片或视频生成任务。HTTPS 网站使用同一套对话界面，渲染通过已授权的本机助手执行；网站不需要安装 Blender。

## 本机工作台

本机工作台默认直接调用 Blender。自动检测 `Blender Foundation` 常见 C/D 盘安装路径、PATH、`JINGCE_BLENDER` 和自定义路径。FFmpeg 从 PATH、`JINGCE_FFMPEG`、`runtime/tools/ffmpeg/bin/` 或 `runtime/tools/video-python/imageio_ffmpeg/binaries/` 检测。也可勾选“通过本机助手渲染”，使用同一套网站流程。

默认 Workbench 渲染，显卡/图形初始化失败时自动回退到 Cycles CPU；也可明确选择 CPU。每个本机执行器串行渲染，最多排队 5 项。预演时长 1–30 秒，支持 12/24/25/30 fps，短边分辨率 360/540/720，比例 16:9、9:16、1:1。没有 ffprobe 也可以导出：使用 FFmpeg 完整解码，并核对帧数、时长、PNG 连续性和尺寸。默认无音频。

## 配置格式

`schemaVersion: 1`，包含 `name`、`duration`、`fps`、`ratio`、`resolution`、`world`、`objects`、`actors`、`camera` 和 `beats`。网页自带完整“庭院相遇”示例。

- 坐标单位为米，Z 向上。地面位于 XY 平面，中心为原点。
- 静态道具 `position` 表示几何中心，`size` 是 XYZ 尺寸，`shape` 支持 `box/sphere/cylinder`，`yaw` 是绕 Z 轴角度。
- 活动主体的 `position` 为脚底/底面位置，`shape` 还支持 `human`；人物默认面向 +Y。路径在 `keys` 中，每个点包含 `time`、`position`，可选 `yaw`。
- 摄影机有 `lens` 和 `keys`，每点必须含 `time`、`position`、`target`。
- 每条路线覆盖 0 秒到总时长，关键点严格递增且不落在同一帧。插值支持 `smooth/linear`。
- `beats` 每项为 `time` 和 `label`，用于时间轴标记和成片提示词。
- 最多 160 个道具、12 个活动主体，每条路线 120 点。配置校验仅检查数据和范围；路径避障与构图仍需从预演检查，不保证自动避免穿模。

## 数据与恢复

任务持久化到现有 `runtime/projects.json` 中的 `previsJobs`，文件位于 `runtime/previs/<任务编号>/`；MP4 和关键帧进入 `runtime/assets/`。工具设置位于 `runtime/previs-settings.json`。网站助手的本机记录在解压目录 `runtime/blender-helper/`，与工作台项目数据隔离。

AI 原始场景、故事草稿与助手连接令牌保存在当前浏览器。站点任务中保留原场景及操作编号，丢失响应后再次提交先返回已有任务。重试保留原规格与任务编号；点击“复制场景继续编辑”再新建预演。网站页面关闭不会终止本机渲染，返回原网站工程并连接同一个助手后继续查原任务并上传文件。上传暂时失败会保留本机结果，可继续保存。助手重启造成渲染中断时，原任务标记失败，保留 `.blend` 与帧序列供重新预演。

工程软删除保留任务与文件；工程仍有预演时禁止彻底删除。任务完成或取消后，彻底删除工程会同时清理预演目录和登记媒体。

## 验证范围

自动化测试覆盖规格校验、任务去重、失败重试、取消、删除清理、授权/CORS、助手上传，以及对话上下文、回复校验、待应用方案绑定和实际改动列表。`node tools/verify-previs-render.mjs` 使用已安装的 Blender 完成真实白模与 MP4 验证。`node tools/verify-previs-browser.mjs` 使用临时工程和模拟文字接口，先复用已渲染媒体检查编辑、播放、连续对话、版本恢复和素材操作，再从模拟 HTTPS 网站连接真实本机助手、调用 Blender、刷新页面恢复原任务并回传输出，应用对话修订后再用真实 Blender 生成新预演；不调用收费生成接口。浏览器脚本需要 Playwright 和 Edge，可用 `JINGCE_BROWSER_MODULES` 指定已有的依赖目录。

已在 Windows、Blender 5.2.2 LTS 和 Edge 验证 2 秒、640×360、12 fps、24 帧输出，完整解码帧数与时长匹配；助手包在含中文和空格的独立目录完成 Node.js 与 FFmpeg 下载准备。浏览器验证中的 HTTPS 页面在本机代理到测试服务，网站云端的 HTTPS、反向代理权限及浏览器本地网络访问仍需在实际部署域名上验收。


## 一次安装与连接入口

下载助手 ZIP 并解压，双击“安装助手.cmd”。程序会保存到当前用户 LocalAppData/JingceBlenderHelper，准备运行环境和编码工具，并创建“幻帧blender助手”桌面入口。Blender 仍需自行安装，助手自动检测。以后双击桌面入口启动并保持助手运行，回到网站点击“连接本机渲染”。首次连接需授权网站并允许浏览器本地网络访问。未检测到助手时，网站保留当前页面并显示操作指引；高级工具设置需要先连接助手。当前不含 Windows 应用协议注册或签名 EXE 安装器。
