# 幻帧管理后台与个人中心

本次为项目的账号管理扩展，保留原项目许可证与非商业使用限制。

## 使用入口

- 登录后的侧栏提供「个人中心」「公告中心」。本站管理员额外看到「管理后台」。
- 管理员由 `JINGCE_ADMIN_EMAIL` 指定，默认 `cl550225778@gmail.com`。这与 Pictora 的 `is_admin` 字段独立；普通 Pictora 管理员不会自动成为本站管理员。
- 两个项目共用邮箱、注册用户名及密码。本站昵称、角色、停用、公告、会话、任务记录均保存在本站。

## 管理后台

- 运营概览：用户、工程、任务状态、素材记录大小、已返回用量、按币种或单位分组的预估费用。
- 用户管理：搜索、启用/停用、授予/撤销管理员、退出用户会话。主管理员无法被停用或降权，管理员不能修改自己的角色或停用自己。
- 公告：草稿、发布、置顶、截止时间和下架；普通用户有独立的已读状态，更新公告会重新标为未读。
- 网站参数：网站名称、支持说明、开放注册、维护模式及每位用户的工程上限。维护模式暂停普通用户的创作修改与提交，仍可查看记录、修改个人资料。
- 云存储：沿用 `runtime/storage.private.json`，支持原有 R2 / COS 参数、保留密钥、连接测试。普通用户没有配置入口，旧写入接口也被拒绝。用户 API 模型连接仍由各账号自行配置。
- 操作日志：账号安全、用户权限、公告、网站设置和云存储变更。

## 个人中心

- 我的概览、跨工程任务中心、费用与用量、公告、昵称、密码和登录设备。
- 任务按类型、状态、时间和关键词筛选，支持详情、状态时间线及 CSV 导出（单次上限 10000 条）。
- 可撤销其他设备会话。修改或找回密码会更新共享密码并撤销所有本站会话；页面明确提示 Pictora 同样使用新密码。
- 验证码重置采用独立用途、冷却时间、尝试次数、一次性使用以及密码更新后的失效处理。

## 数据与费用说明

- `runtime/management.sqlite`（以及 SQLite WAL/SHM）保存本站管理数据与任务账册；备份运行目录时一起保留。
- 发布时导入各 `runtime/users/<id>/projects.json` 的现有任务元数据，不触发任何生成。
- 后续图片、视频、配音、音色、预演的状态变化写入账册。删除工程或结果不会抹掉账册。新文字请求记录状态与返回的 token 用量，不保存提示词、正文或密钥。
- 历史任务只有原记录中已有的报价和用量。无法重建先前未记录的数据；历史时间线从导入时的已知状态开始。
- 新图片任务冻结每张候选的报价区间，批量任务不会把整批报价重复累计。
- 预估费用包含失败和已删除的任务，不代表实际扣款。没有服务商实际账单时，实际扣费显示「未提供」。没有余额、充值或退款系统。
- 全站存储读取统一配置，新参考素材对象路径为 `<prefix>/users/<userId>/assets/...`。已有存储配置与旧对象保留，不批量删除或移动素材。

## 验证与部署

```powershell
npm test
$env:JINGCE_PLAYWRIGHT_MODULE = '<已安装的 playwright 模块绝对路径>'
node tools/verify-auth-browser.mjs
node tools/verify-management-browser.mjs
```

浏览器脚本使用临时数据库及假服务，不修改生产密码、不发送真实注册邮件、不提交收费生成任务。截图存放在已忽略的 `outputs/`。

生产运行 `jingce.service`，目录 `/opt/jingce-ai-workbench`。部署只替换应用代码，保留 runtime 与 `/etc/jingce-auth.env`。回滚代码时不要覆盖部署之后的工程、账号密码、会话和管理数据库；若需回滚权限管理，先评估旧代码没有本站停用限制的影响。
