# 服务器部署与同步

生产地址：https://dream.beibeihai.xyz/

GitHub `main` 为代码来源。部署改为手动执行，只有用户明确提出部署请求时才更新服务器；拉取代码或推送 GitHub 不触发部署。服务器不再安装自动部署脚本、服务或定时器。

服务器代码目录：`/opt/jingce-ai-workbench`。应用服务为 `jingce.service`。Nginx 和 HTTPS 配置由服务器管理。

工程、媒体文件和私有配置保存在 `runtime/`，不会推送到 GitHub，也必须在部署和回滚时保留。R2 密钥位于 `runtime/storage.private.json`，权限为 `0600`。R2 支持仅用于生成时上传选中的参考素材；工程数据库和本地原始素材仍保存在服务器。

R2 设置中选择 Cloudflare R2，填写桶名、S3 Endpoint、Access Key ID 和 Secret Access Key。地域固定为 `auto`，参考素材链接采用临时签名链接。连接测试会上传一个小图片、核对读取内容并删除测试对象，不调用生成模型。

## 查看状态

```bash
systemctl status jingce.service
journalctl -u jingce.service -n 80 --no-pager
cd /opt/jingce-ai-workbench
git rev-parse HEAD
git status --short
```

服务器提交可以落后于 GitHub；用户未提出部署请求时，保持现有线上版本。若服务器源代码有未发布修改，先审查并保存改动，避免在更新时覆盖。

## 手动部署流程

1. 确认用户已明确要求部署，读取 GitHub 最新提交并记录当前生产提交，检查服务器工作区是否干净。
2. 在独立的临时目录检出待部署的确定提交，按项目要求安装依赖并执行 `npm test`；测试不通过时保留线上版本，并说明失败原因。
3. 测试通过后，备份 `runtime/`，将服务器源码快进更新至已验证的提交并安装所需依赖，重启 `jingce.service`。
4. 检查应用服务、HTTPS 首页和 `/api/bootstrap`。仅记录状态码及必要的健康信息，避免输出会话令牌和私有项目数据。
5. 更新后检查失败时，恢复记录的上一生产提交及对应依赖，再重启并验证服务。回滚仅调整源码和依赖，保留 `runtime/` 中的工程、媒体和私有配置。

部署完成后记录生产提交编号和验证结果。需要再次部署或回滚时，由用户主动提出请求，不进行定时检查或自动重试。

部署源码时保留现有域名证书和 Nginx 配置；基础设施变更需要单独验证。当前仓库公开，因此服务器拉取无需保存 GitHub 凭据。
