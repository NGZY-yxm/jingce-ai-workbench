# 服务器部署与同步

生产地址：https://dream.beibeihai.xyz/

GitHub `main` 为生产代码来源。服务器每分钟检查新提交，先在隔离目录执行 `npm test`，通过后再快进更新代码、重启服务和检查应用接口。测试失败时保持原版本；更新后健康检查失败时恢复上一提交。检查耗时和测试耗时会增加实际部署等待时间。

服务器代码目录：`/opt/jingce-ai-workbench`。应用服务为 `jingce.service`，自动部署服务为 `jingce-deploy.service`，定时器为 `jingce-deploy.timer`。Nginx 和 HTTPS 配置由服务器管理。

工程、媒体文件和私有配置保存在 `runtime/`，不会推送到 GitHub或被源码更新覆盖。R2 密钥位于 `runtime/storage.private.json`，权限为 `0600`。R2 支持仅用于生成时上传选中的参考素材；工程数据库和本地原始素材仍保存在服务器。

R2 设置中选择 Cloudflare R2，填写桶名、S3 Endpoint、Access Key ID 和 Secret Access Key。地域固定为 `auto`，参考素材链接采用临时签名链接。连接测试会上传一个小图片、核对读取内容并删除测试对象，不调用生成模型。

## 查看状态

```bash
systemctl status jingce.service jingce-deploy.timer
journalctl -u jingce-deploy.service -n 80 --no-pager
cat /var/lib/jingce-deploy/status.json
cd /opt/jingce-ai-workbench
git rev-parse HEAD
git status --short
```

`status.json` 只记录提交编号、状态和检查时间。正常状态为 `synchronized`。若服务器源代码有未发布修改，自动部署会停止，避免覆盖修改；先将改动审查并推送至 GitHub，再恢复同步。今后修改代码应从 GitHub 推送，服务器作为部署目标。

## 安装或维护自动部署

```bash
cd /opt/jingce-ai-workbench
install -m 755 tools/deploy/update-server.sh /usr/local/sbin/jingce-auto-deploy
install -m 644 tools/deploy/jingce-deploy.service /etc/systemd/system/jingce-deploy.service
install -m 644 tools/deploy/jingce-deploy.timer /etc/systemd/system/jingce-deploy.timer
systemctl daemon-reload
systemctl enable --now jingce-deploy.timer
systemctl start jingce-deploy.service
```

失败提交记录在 `/var/lib/jingce-deploy/rejected-commit`，相同提交不重复部署。推送修复提交后会自动重试；确认只是外部网络暂时故障时，可以删除该记录并手动启动部署服务。并发部署由文件锁保护。

自动部署只覆盖生产应用源码，不修改域名证书和 Nginx；此类基础设施变更需要单独部署验证。当前仓库公开，因此服务器拉取无需保存 GitHub 凭据。
